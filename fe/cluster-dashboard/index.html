Build the cluster

Replication factor stays fixed as machines grow. Putting every shard on every machine would make a 9-machine cluster need a quorum of 5 — adding hardware would make writes slower and less available. With RF=3 and 9 machines, most machines hold only some shards, so some hold no copy of a given account at all.
Rebuilding is a teaching control: a live cluster would migrate replicas (resharding, deliberately out of scope). Accounts are replayed at their opening balance.

Each shard's CAP verdict

A shard commits only when a majority of its machines agree. Below that it faces the CAP choice: accept a write no majority has seen (AP — and risk two machines accepting conflicting withdrawals of the same money), or refuse (CP). This system chooses CP: it would rather tell you it cannot serve than tell you something false about your money.

Machines

Every machine hosts a replica of every shard, so killing one costs each shard a replica at once. 3 machines → majority is 2: survive one loss, refuse writes after two, go dark after three.
Try it:pick a shard, then and watch the entry land on the leader first.

Which shard's log

on this machine, not yet committed committed — a majority stored it applied — folded into the balance
Every machine holds the same log in the same order, so replaying it gives the same balance everywhere — that is why replication is possible at all. The leader appends first; an entry becomes committed only once a majority has stored it, and only then is it applied.

Who leads what, right now

One leader per shard, not one per cluster. Kill a leader and only that shard re-elects — the others carry on, which is why the term numbers drift apart. A machine can lead one shard while following another.

Inside each machine

A machine is not a shard. Each row is one replica — one copy of one shard's log living on this machine. commit is how far a majority agreed; applied is how far this replica folded into its balances. Applied trailing commit is normal and momentary; applied trailing the other replicas is what "lagging" means.

Balances derived from those logs

Balances are a fold over the log, never the thing copied. Two machines showing different balances means one has applied fewer entries — not that the data diverged.

Event log — what happened, and who caused it

client is an operation someone asked for. raft is the cluster acting on its own — elections, catch-up, re-replication — which is the part no click causes. control is this dashboard killing or reviving machines.

Watch for INDETERMINATE: the entry is in the leader's log and may still commit. It is not a refusal, and the correct response is to retry with the same idempotency key.
